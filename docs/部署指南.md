# Henfon Shop 部署指南

## Docker 本地编排

1. 复制 `.env.example` 为 `.env`，替换所有 `change-me` 值。
2. 执行 `docker compose up -d --build` 构建并启动管理端、MySQL、Redis 和 MinIO。
3. 首次启动时 MySQL 会按 `shop-admin/db/init` 的版本顺序执行初始化脚本；后续变更先运行 `shop-admin/db/migration/verify-migrations.ps1`。
4. 通过 `http://localhost:8080/actuator/health` 检查管理端健康状态，MinIO 控制台地址为 `http://localhost:9001`。

RocketMQ 默认使用宿主机 `9876` 端口；生产环境应将 `ROCKETMQ_NAME_SERVER` 指向高可用 NameServer 集群，并单独部署 Broker。

## 生产环境变量

生产环境必须注入 `SHOP_MYSQL_URL`、`SHOP_MYSQL_USERNAME`、`SHOP_MYSQL_PASSWORD`、`SHOP_REDIS_HOST`、`SHOP_REDIS_PASSWORD`、`SHOP_JWT_SECRET`、`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY` 和 `ROCKETMQ_NAME_SERVER`。微信支付证书、私钥及回调地址通过对应 `SHOP_WECHAT_PAY_*` 变量提供，禁止写入镜像或仓库。

## 发布与回滚

- 镜像使用不可变 Git 提交或版本标签，例如 `henfon/shop-admin:<commit-sha>`，禁止直接覆盖 `latest`。
- 发布前先执行健康检查、数据库迁移清单校验和核心接口冒烟；滚动更新时至少保留一个上一版本实例。
- 新版本异常时，将编排文件中的镜像标签改回上一版本并执行 `docker compose up -d shop-admin`；数据库变更仅允许向前兼容，禁止直接回滚已执行的 SQL。
- 灰度流量切换由网关或容器平台完成，切换前后均检查 `/actuator/health`、错误率和消息堆积。
