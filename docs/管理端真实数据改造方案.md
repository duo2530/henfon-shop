# 管理端真实数据改造方案

## 1. 改造目标

管理端的业务数据以服务端接口和数据库为唯一事实来源。接口失败、超时、无权限或返回空数据时，前端不得继续展示本地演示数据，也不得用虚构的业务统计替代真实结果。

本次改造同时解决系统设置无法持久化、物流承运商分散写死以及前端乐观更新失败后状态不一致的问题。

## 2. 当前问题清单

### 2.1 高优先级

1. `shop-web/src/context/AdminContext.tsx` 使用 `rbacMockData.ts` 初始化角色、系统用户、部门和数据权限规则。接口失败或返回空数组时，可能继续显示本地演示数据。
2. `shop-web/src/components/settings/SettingsView.tsx` 将店铺信息、库存阈值、通知开关和支付开关保存在前端状态，当前只有运费模板真正读写服务端。
3. `shop-web/src/components/products/ProductManagementView.tsx` 在类目接口不可用时使用 `fallbackCategoryOptions`。
4. `shop-web/src/components/orders/OrderManagementView.tsx` 和系统设置页面将承运商默认值写死为顺丰速运。
5. `shop-web/src/data/mockData.ts` 仍保留商品、订单、会员和通知演示数据，存在后续误引用风险。

### 2.2 中优先级

1. 多个页面使用固定的批量查询大小，这是请求策略，不属于业务数据，但后续应统一分页策略。
2. 部分写操作先修改本地状态再调用接口，失败时只提示而没有统一回滚或重新同步。
3. 表单中的退款原因、物流字典、支付渠道等可变业务选项仍由前端维护。

## 3. 实施顺序

### 阶段一：清除假数据和本地业务兜底

- RBAC 状态改为空数组初始化。
- RBAC 接口失败时清空对应数据并展示错误状态。
- 接口返回空数组时明确使用空状态，不保留初始演示数据。
- 删除商品类目本地兜底，接口失败时禁止提交依赖类目的商品。
- 确认并清理未使用的 `mockData.ts` 和 `rbacMockData.ts`。

### 阶段二：系统设置接口化

- 新增租户隔离的系统配置表。
- 新增系统配置查询、保存和恢复默认值接口。
- 店铺信息、库存预警、通知、支付和物流开关全部从服务端读取并保存。
- 页面增加加载、错误、空值和保存状态，保存成功后重新读取服务端数据。

### 阶段三：物流字典统一

- 新增可启用的物流承运商字典接口。
- 系统设置、订单发货和批量发货统一读取物流承运商。
- 删除各页面的顺丰默认值和重复承运商选项。
- 运费模板只保存后端返回或用户选择的承运商。

### 阶段四：写操作一致性和回归验证

- 统一采用“接口成功后刷新”或“乐观更新失败回滚”的策略。
- 统一处理 401、403、网络错误、空结果和接口 5xx。
- 执行前端静态检查、后端编译和浏览器 MCP 冒烟测试；后端单元测试保留为后续专项补充。
- 验证数据库修改后刷新页面能够得到新数据，接口失败时不出现演示数据。

## 4. 后端设计

### 4.1 系统配置表

建议表名：`system_config`。

核心字段：

- `id`
- `tenant_id`
- `config_key`
- `config_value`
- `value_type`
- `description`
- `status`
- `version`
- `created_at`
- `updated_at`
- `is_deleted`

配置键建议：

```text
store.name
store.contact.phone
store.contact.email
inventory.low_stock_threshold
notification.auto_email
logistics.auto_tracking_sync
payment.wechat_enabled
logistics.default_carrier
logistics.remote_regions
```

### 4.2 系统配置接口

```text
GET /api/admin/system/config
PUT /api/admin/system/config
POST /api/admin/system/config/reset
```

要求：

- 按租户隔离。
- 后端初始化默认值，前端不再维护业务默认值。
- 保存接口使用版本号防止并发覆盖。
- 配置变更写入操作日志。
- 返回统一的配置对象和版本号。

### 4.3 物流承运商接口

```text
GET /api/admin/system/dictionaries/logistics-carriers
```

返回承运商编码、名称、启用状态和排序值，供设置页和订单发货页共用。

## 5. 前端数据原则

可以写死：分页大小、状态枚举展示名、图标、颜色、格式化规则和“暂无数据”等界面提示。

不能写死：商品、订单、会员、角色、部门、数据权限、店铺资料、物流公司、支付开关、库存阈值和可变业务字典。

## 6. 验收标准

1. 删除或禁用本地业务模拟数据后，管理端核心页面仍能正常加载真实接口数据。
2. 接口返回空数组时页面显示空状态，不显示演示记录。
3. 接口异常时页面显示错误和重试入口，不显示演示记录。
4. 系统设置修改后刷新页面仍保持修改结果。
5. 商品、订单、会员、RBAC 和报表数据均可通过浏览器网络面板确认来自接口。
6. 所有新增或修改的 Java 方法包含作者 `Henfon`、日期和描述注释。
7. 不执行未经用户同意的 Git 提交或推送。

### 7.1 已完成的实现

- 删除管理端 RBAC 与商品类目的本地模拟数据文件；接口返回空数组或失败时清空页面数据。
- 系统设置改为租户级服务端配置，增加版本校验、保存、重置接口；运费模板名称不再绑定单一物流公司。
- 新增 `sys_dictionary_item` 与物流承运商查询接口，设置页、单笔发货、批量发货共用服务端字典。
- 删除订单发货页面的顺丰默认值和虚构运单号；批量发货必须录入真实运单号。
- 删除系统用户新建时虚构手机号、邮箱和固定初始密码；修复系统用户编辑误调用删除接口的问题。
- 写操作失败时对商品状态、会员资料、订单审核、备注、退款和系统用户等场景进行回滚或重新拉取服务端快照。

### 7.2 尚未纳入本轮的范围

- 代客录单页面目前只有前端表单，后端没有订单创建管理接口；现改为明确提示不可创建，不再生成本地假订单。
- 操作日志记录能力已有基础设施，但系统配置保存的专用操作日志补充需要结合现有审计切面继续接入。
- 浏览器 MCP 已验证管理端真实接口：系统配置、物流承运商字典、RBAC 部门和系统用户接口返回 200；设置页能够展示服务端物流字典，刷新后仍从服务端加载。
- 通过 `npm run lint`、管理端 Maven 编译和 `git diff --check`；未执行 Git 提交或推送。
