# 门户页面化改造方案

把个人中心、收藏、商品详情、商品参数对比这四个弹层改成独立页。

## 结论

难度不大，但工作量不在「搬 JSX」。

门户所有打开入口都汇聚到 `App.tsx` 的几个回调上，子组件只负责渲染。所以改这几个回调的语义就等于改掉了全部入口 —— 这一点在「我的订单」改整页时已经验证：改动集中在 `App.tsx` 与一个新组件里，`ProductCard`、`Navbar` 这些下游只动了一行 `onNavigateHome`。

真正要先解决的是两件共用的事，四个页面都依赖它们：

1. **路由层**。现在是 `PortalView = 'home' | 'orders'` 加一个 `readPortalViewFromHash()` 的临时写法，每加一个视图要同时改类型、解析函数、`pushState` 分支、监听四处。加到 6 个视图之前应该先抽成正经的（仍然不引依赖，自写约 80 行）。
2. **跳走再回来，原来的筛选和选中还在不在**。`OrdersPage` 的状态筛选、选中订单、窄屏的列表/详情切换都是组件内 state，一旦跳去商品详情就被卸载。这条不解决，页面之间来回跳的体感会比现在弹层更差。

## 四个视图的现状

| 视图 | 组件 | 行数 | 自己调接口 | 打开入口 |
| --- | --- | --- | --- | --- |
| 收藏 | `WishlistModal.tsx` | 112 | 无 | 2 处：顶部收藏按钮、个人中心「心愿收藏」卡 |
| 参数对比 | `CompareModal.tsx` + `CompareChartsView.tsx` + `CompareFloatingBar.tsx` | 2589 | 无 | 1 处：底部对比浮层条的「展开对比」 |
| 商品详情 | `ProductQuickView.tsx` | 1318 | 评价分页 + 提交（详情由 App 拉） | 5 条链路：列表卡片、轮播商品位、收藏、对比、订单评价 |
| 个人中心 | `UserProfileModal.tsx` | 709 | 我的评价 + 缺失商品名逐个补详情 | 3 处：顶部头像区、订单页已评价商品的「查看」、商品详情的「查看我的评价」 |

按耦合度排序（不是按行数）：收藏最轻，对比行数最多但纯 props 输入、最容易；商品详情体积最大且要拆三条「叠层跳转」；个人中心带自己的取数、内部还有三个子视图。

## 前置一：路由层

### 现在的问题

`App.tsx:126` 定义 `PortalView`，`:129` 用 `readPortalViewFromHash()` 解析，`:1033` 的 `navigatePortalView` 压一条 history，`:1041` 监听 `popstate`/`hashchange`。

其中有个已实测出来的 bug：跳过导航链接 `<a href="#portal-main-content">` 与 hash 路由共用同一段 hash。在订单页点它，`hashchange` 触发、解析函数认不出这个 hash、视图被打回首页（复现：进 `#/orders`，执行 `location.hash = 'portal-main-content'`，订单页立刻消失）。这类坑会随视图数量成倍放大，所以随阶段 0 一起修掉了。

### 方案 A（推荐）：自写路由表，不引依赖

新增 `src/utils/portalRoute.ts`（约 60 行）与 `src/hooks/usePortalRoute.ts`（约 20 行）：

```ts
type PortalRoute =
  | { view: 'home' }
  | { view: 'orders'; status?: string; orderId?: number }
  | { view: 'product'; productId: string; tab?: 'details' | 'specs' | 'reviews' }
  | { view: 'wishlist' }
  | { view: 'account'; section?: 'profile' | 'coupons' | 'reviews'; productId?: number }
  | { view: 'compare' };
```

三个约束写进解析函数：

- 只认 `#/` 开头的 hash。`#portal-main-content` 这类锚点原样忽略，保持当前视图不变 —— 这直接修掉上面的 bug。
- 未知 `#/xxx` 回首页，并且不静默：`#/product/999999` 要能落到「商品不存在」而不是空白。
- 页内状态进查询串：`#/orders?status=shipped&order=26`、`#/product/prod-7?tab=reviews`、`#/account/reviews?product=7`。这是刷新后状态还在的唯一诚实做法。

继续用 hash 而不是 path 路由还有一个部署理由：门户没有配 `base`、也没有前端服务器做 rewrite，构建产物是交给静态托管直接发布的，hash 路由不需要任何服务端配合。

### 方案 B：装 react-router-dom

能拿到的是多级路由、`useParams`、`ScrollRestoration` 这些现成件，以及社区惯例。代价是多一个依赖，而且它的数据加载能力（loader）用不上 —— 门户的数据和 handler 全在 `App.tsx` 里，页面组件本来就是纯展示。

判断标准：如果四个页面之后还要继续长（比如加「我的地址」「发票管理」「用券历史」这些独立页），到那时切 B；现在 6 个扁平视图，A 够用且更好读。

## 前置二：跳转后的状态保留

三个选项：

- **全部保活**（沿用现在首页↔订单页的 `display` 切换）。好处是零思考、状态天然不丢；坏处是每加一页就多一份常驻 DOM 与活着的 effect，商品详情那种带评价分页、视频播放器的组件挂着不合适。
- **状态进 URL**。`#/orders?status=shipped&order=26` 这类。好处是刷新、分享、前进后退都对，也不需要保活；坏处是要把 `OrdersPage` 里三个 state 改成受控。
- **现取现丢**。最省事，但和你的既有约定冲突（返回列表要保留筛选与页码）。

建议：首页保持保活（它挂着轮播、类目树、商品列表好几个请求，卸载会闪白 —— 这条现在已经在做），**其余页面一律走 URL 承载状态**。具体要搬的三个：订单页的 `statusFilter`、`selectedOrderId`，商品详情的 `quickViewTab`。

顺带能删掉两处 hack：现在「订单点查看评价 → 个人中心」靠 `reviewsViewToken` 递增 + `highlightReviewProductId` 两个 state 传递，`#/account/reviews?product=7` 之后刷新都能定位；`quickViewTabToken` 同理。

## 四个视图怎么改

### 收藏（最容易，先做这个）

去掉 `fixed inset-0` 外壳和 `useBodyScrollLock`，列表部分原样搬进页面，补面包屑与「共 N 件」标题。`onQuickView` 从「关弹层 + 开商品弹层」改成跳 `#/product/xxx`，返回靠浏览器后退。

一个待定项：现在未登录也能打开收藏（本地收藏状态，空列表就看空态）。页面化之后 `#/wishlist` 对未登录用户是照常显示空态，还是重定向回首页，需要定（见「要拍板的」）。

### 参数对比（行数最多但最简单）

`CompareModal` 与 `CompareChartsView` 都不调接口、数据全由 props 传入，所以这两个基本是原样搬。真正要处理的是三处交互语义：

- `onClose` 里现在顺手存一次对比历史（`saveCompareHistory`）。页面没有「关闭」了，改成离开路由时存，或者进入页面时存一次。
- 底部对比浮层条要在这个页面上隐藏，否则它浮在对比页上、点它还能再「打开」一次自己。
- 「加入购物车 / 批量加购」的 `addedItemIds` 等状态本来就是页内状态，不需要动。

### 商品详情

`ProductQuickView` 里已经拆好了：外层 6 行的壳 + 内层 `ProductQuickViewContent`（拿非空 product）。所以外壳换成页面容器（面包屑 + 返回 + `max-w-7xl` 主容器），`max-h-[92vh]` 的内层滚动换成自然滚动，主体 JSX 不用动。

要动的是状态来源：现在 `quickViewProduct` 存的是整个商品对象，刷新就没了。改成路由只认商品 ID，复用现成的 `openProductById` + `createProductStub` + `loadProductQuickView`（这里面已有 requestId 竞态保护）。好处是刷新、分享商品链接都能用。

三条要拆的叠层跳转：

| 现在 | 改成 |
| --- | --- |
| 收藏 → 关弹层 → 开商品弹层 | 收藏页 → `#/product/xxx` |
| 对比 → 关弹层 → 开商品弹层 | 对比页 → `#/product/xxx` |
| 订单「评价」→ 商品弹层叠在订单页上 | 订单页 → `#/product/xxx?tab=reviews` |

第三条是唯一会丢状态的：从订单页跳走再返回，订单页的筛选与选中订单要么靠 URL 承载（见前置二），要么接受丢失。

还有一个细节：现在从订单页进评价、关掉弹层就回到原订单，一层返回就够了；改成跳转后是两次后退。可以用 `replaceState` 让订单页那次跳转不额外压栈，行为持平。

### 个人中心

内部三个视图（资料详情 / 编辑表单 / 我的券包）加「我的评价」，正好对应 `#/account`、`#/account/coupons`、`#/account/reviews` 三个子路由。改成子路由之后有两个直接收益：券包能直接分享/刷新，评价定位不再依赖 token。

自带的取数是 `fetchPortalMyReviews(1, 20)` 加对缺失商品名逐个 `fetchPortalProductDetail`。现在这个 effect 的开关是 `isOpen && user`，页面化后变成「进入路由才跑」，行为不变；但要注意它不能再跑在未登录状态下（`user` 为空时直接跳过，现在也是这么写的）。

退出登录按钮要补一个回首页，现在靠 `onClose()` 收掉弹层。

## 要你拍板的四件事

1. **未登录访问 `#/account`、`#/wishlist`**：照常渲染空态，还是重定向回首页并拉起登录弹层？我倾向后者（账号页空着没意义），但收藏保持前者（先收藏再登录是合理的）。
2. **订单页跳商品详情再返回，筛选和选中订单保不保**：保就走 URL 承载（多改 `OrdersPage` 三处 state），不保就现取现丢（少改，但体验倒退）。
3. **对比页空集合**：现在浮层条在没有商品时自己会收起。页面化后 `#/compare` 无商品时显示空态页 + 返回首页，可以吧？
4. **页面宽度**：四个页面统一走首页那套 `max-w-7xl` 左栏 + 主区两栏，还是商品详情独占更宽？我倾向统一，商品详情不占左栏（类目树在商品页没有意义）。

这四个问题在实施中已经定下来了：未登录进 `#/account` 回首页并拉起登录（收藏不在此列，照常显示空态）；订单页的页签与选中订单走 URL 承载（阶段 4 补的）；`#/compare` 无商品时显示空态页而不弹回首页；四个页面统一走首页那套 `max-w-7xl`，左栏只在 `route.view === 'home'` 时渲染。

## 实施顺序

每步都能独立交付、独立验证，不用等全部做完。

| 阶段 | 内容 | 验证口径 |
| --- | --- | --- |
| 0 | 抽路由层，把 home/orders 迁过来，修掉锚点 hash 冲突 | 界面无变化；`#portal-main-content` 不再改变视图；订单页刷新/后退行为与现在一致 |
| 1 | 收藏页面化 | 列→跳商品→返回，收藏数、滚动位置正常 |
| 2 | 对比页面化 | 浮层条在对比页隐藏；离开时对比历史落库；图表页签正常 |
| 3 | 商品详情页面化 | 四条入口链路都能进；`?tab=reviews` 刷新后仍在评价页签；直接打开不存在的商品 ID 有明确提示 |
| 4 | 个人中心页面化 | 三个子路由刷新都在；订单「查看评价」能定位到目标评价；退出登录回首页 |

阶段的顺序还有一层考虑：路由层先做，后面每步都能顺手用 URL 承载状态，不用回头改。收藏放第一步是因为它最小，能把「列表页 → 跳转 → 返回」这条链路完整跑通一次，后面三步重复同一套模式。

进度：阶段 0、1、2、3、4 已完成，四个弹层全部改成独立页。

- 阶段 0：路由层落在 `src/utils/portalRoute.ts` 与 `src/hooks/usePortalRoute.ts`，`App.tsx` 里原来的 `PortalView` / `readPortalViewFromHash` / `navigatePortalView` 三段已删。跳过链接同时加了 `preventDefault` + 手动移焦点 —— 光靠解析器忽略锚点还不够，链接本身会把 `location.hash` 冲成 `#portal-main-content`，此时刷新就掉回首页。
- 阶段 1：收藏页落在 `src/components/WishlistPage.tsx`，`WishlistModal.tsx` 已删除。未登录照常显示空态。
- 阶段 2：对比页落在 `src/components/ComparePage.tsx`（外壳换成面包屑 + 标题 + 卡片，内部 JSX 原样保留），`CompareModal.tsx` 已删除。底部批量操作条改成 `sticky bottom-0`；对比浮层条在对比页上隐藏；离开页面（`handleLeaveComparePage`）时存一次对比历史，沿用原来「关闭即留档」的行为；「清空」不再关页面，改为停在 `#/compare` 显示空态。
- 阶段 3：商品详情页落在 `src/components/ProductDetailPage.tsx`，`ProductQuickView.tsx` 已删除。商品 ID 与页内页签都进地址（`#/product/<id>?tab=&variant=`），刷新与分享链接能落到同一个商品、同一个页签；页签切换用 `replaceState`，不额外压历史。`App.tsx` 里 `quickViewProduct` / `quickViewTab` / `quickViewTabToken` / `quickViewVariantSeed` 四个状态合并成「路由 + `currentProduct`」，商品数据由路由监听统一去取（`useLayoutEffect`，避免切商品时闪一下上一件商品）。

几处实现口径，和当初的预判有出入的地方记在这里：

- 商品 ID 在解析时就归一化成 `prod-<数字>`。地址栏、Banner 的 `linkTarget`、订单明细里 `7` 与 `prod-7` 两种写法都有，不归一化同一个商品会有两个地址；归一化函数 `normalizeProductId` 同时替掉了 `App.tsx` 里原有的一份重复实现。
- 残缺地址 `#/product`（只有路径没有 ID）回首页，不停在一个没有商品的商品页上。
- 「加入购物车 / 立即购买 / 收藏」不再把用户送走。旧弹层必须关掉自己才能回到首页，整页视图没有这个约束：加购留在商品页并弹提示，直购把结算浮层叠在商品页上，关掉结算仍然回到刚才那个商品。
- 对比浮层条改成**只在首页显示**（原来是「除对比页外都显示」）。它固定在视口底部，在整页视图上会压住正文与吸底操作条 —— 这是阶段 1 就发现的既有问题，这批一起收掉。
- 商品详情页从订单页跳过去仍然是「一次后退回到订单页」，与旧弹层体验持平。
- 阶段 3 结束时还剩一条叠层跳转：商品页的「查看我的评价」打开的是个人中心浮层。这一条在阶段 4 一起收掉了。

阶段 4 的落点与前后差异：

- 个人中心落在 `src/components/UserProfilePage.tsx`，`UserProfileModal.tsx` 已删除。三个子视图改成地址：`#/account`（资料与特权，缺省）、`#/account/coupons`、`#/account/reviews`，转成页签在页面上切换。`#/account/profile` 与 `#/account` 归一化成同一个地址，同一个画面不留两种写法。
- 评价定位不再靠「递增标记 + `highlightReviewProductId`」：目标商品直接进地址（`#/account/reviews?product=65`），刷新与分享链接都能落回同一条评价；`reviewsViewToken` / `highlightReviewProductId` 两个 state 一并删掉。
- 三条入口（顶栏头像、订单已评价商品行的「查看」、商品页的「查看我的评价」）全部改走路由，`App.tsx` 里不再有个人中心弹层。
- 退出登录补了回首页：弹层时代靠 `onClose()` 收掉，整页形态下退出后停在账号页没有意义。
- 未登录直接敲 `#/account` 会回首页并拉起登录弹层（收藏页不在此列，照常显示空态）。
- 页脚的「编辑资料 / 保存修改」仍是组件内 state：它是表单的临时中间态，进地址反而会让后退多出一堆草稿地址。

订单页的页内状态（阶段 3 记下的那项遗留）在这一阶段一起补上了：

- `statusFilter` 与 `selectedOrderId` 改由地址承载（`?status=shipped&order=22`），`activePane` 不再单独存一份 state —— 选中订单就是「停在详情」的意思，两处状态并存迟早对不上。
- 页内回写用 `replaceState`：每点一单压一条历史的话，后退要按好几下才出得去。
- 实测闭环：订单页 `?status=finished&order=22` → 商品页评价页签 → 个人中心评价 → 后退两次，页签仍停在「已完成」、右栏仍是那一单。
- 换页签会清掉选中项：新列表里那一单未必还在，留着会在窄屏上直接落到详情。

## 顺带发现：门户的 `tsc --noEmit` 检查不到 React 类型

`shop-portal` 与 `shop-web` 都没有装 `@types/react`，且 tsconfig 没开 `strict`，于是 `import React from 'react'` 被当成 `any`：
`tsc --noEmit` 一直是绿的，但**组件的 props、JSX 属性、hook 泛型全都没被检查**。这轮改 `OrdersPage` 时它露了出来 ——
`statusFilter = 'all'` 这个解构默认值因为拿不到 props 类型而推成 `string`，`tsc` 才报了第一处真实错误。

两个可行做法：

- 短期：给改动的组件参数补显式标注 `=(props: XxxProps) =>`，至少让这一个组件的 props 受检（`OrdersPage` 与 `UserProfilePage` 已这么写，加标注后 `tsc` 全绿）。
- 长期：装 `@types/react` + `@types/react-dom`，然后把 `strict` 逐步打开。这会一次性暴露出过去几年在 `any` 下写下的问题，属于独立的一件事，别和页面化混在一起做。

在此之前，**别把 `tsc` 通过当成「属性传对了」的证据** —— 真正守住契约的是 `tests/component-smoke.tsx` 里的静态渲染断言。

## 测试影响

- `tests/a11y-smoke.ts` 按文件名 `readFileSync` 读组件源码，四个文件改名后路径要同步；它现在还对 `ProductQuickView` 断言 `!props.product.title`、`playVideoSafely`、`AbortError` 三处，这些逻辑保留，断言不用改。
- `tests/component-smoke.tsx` 对 `ProductQuickView` 有 4 处 `renderToStaticMarkup` 断言。页面化后它不再接收 `null` product（由路由兜底），这几处要改成新契约。
- `tests/e2e-flow-smoke.ts` 是纯接口级，不受影响。
- 页面语义要替换掉弹层语义：去掉 `role="dialog"`、`aria-modal`、Escape 关闭与焦点陷阱，改成 `<h1>` + 路由切换后把焦点移到标题。漏掉会留一堆「按 Escape 什么都不发生」「Tab 出不去」的残留 —— a11y 测试目前对券弹层断言了 `aria-modal`，改造时别误伤那一条。

四个页面都落地后，测试里的实际口径：

- `tests/a11y-smoke.ts` 读的是页面文件名（`ProductDetailPage.tsx`、`UserProfilePage.tsx` 等），并对每个整页断言「不得出现 `useBodyScrollLock` / `'Escape'` / `aria-modal`」。`App.tsx` 那边断言不再出现 `UserProfileModal`、且有 `route.view === 'account' && currentUser` 分支。
- `tests/component-smoke.tsx` 覆盖：路由解析与生成的闭环（含 `#/orders?status=&order=`、`#/account/coupons`、`#/account/reviews?product=`）、四条整页的静态渲染、订单页 URL 承载的筛选与选中项、个人中心三个子视图互不串内容。静态渲染不跑 effect，所以评价列表只能断言空态文案，真实取数在浏览器里验。
- Escape / 焦点陷阱：整页视图本来就没有，没做额外处理；「路由切换后把焦点移到标题」这项也没做（各整页都没有 `tabIndex={-1}` 的 h1），它不在本轮改动范围内。

## 顺带说明

- 页面化不会让 `App.tsx` 变小。现在 3266 行，其中大头是业务 handler（下单、支付轮询、库存、购物车同步），这些不会因为视图形态改变而消失；四个 `is*Open` state 换成路由判断，行数大致持平。真要瘦身是另一件事（把 handler 收进自定义 hook 或 context），可以放到页面化之后单独做。
- 管理端（`shop-web`）是同样的弹层风格，但这次不动。
